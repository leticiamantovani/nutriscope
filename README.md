## What it does

NutriScope helps people understand the ingredients in packaged food. A user enters a product name or barcode, and the application:

1. Finds the product in Open Food Facts.
2. Extracts and normalizes its ingredient data.
3. Uses an AI workflow to classify each ingredient.
4. Streams a short explanation to the interface.

Each ingredient receives one of four labels: `adequate`, `moderate`, `avoid`, or `carcinogenic`.

NutriScope is an educational tool. Its results are generated by AI and are not medical advice.

## AI engineering

The backend uses a LangGraph workflow with four focused nodes:

1. **Structure input:** Gemini extracts a product name and brand from natural language. Barcodes skip this extraction.
2. **Retrieve product:** the application searches Open Food Facts and selects a product with usable ingredient data.
3. **Classify ingredients:** Gemini returns validated structured output through Pydantic models.
4. **Generate explanation:** Gemini produces a concise answer that is streamed to the client.

The graph keeps retrieval, classification, and generation separate. This makes each step easier to inspect, test, and replace. Product data grounds the model prompts, while structured output keeps ingredient labels consistent with the frontend contract.

## Architecture

```text
Next.js client
    |
    | POST /analyze
    v
FastAPI SSE endpoint
    |
    v
LangGraph workflow
    |
    +--> Gemini for extraction, classification, and explanation
    |
    +--> Open Food Facts for product and ingredient data
```

The API sends Server-Sent Events as the graph runs. The interface can show progress, classified ingredients, generated text, completion, and errors without waiting for the full workflow to finish.

## Tech stack

**Frontend:** Next.js 16, React 19, TypeScript, Tailwind CSS, shadcn/ui, TanStack Query, Framer Motion

**Backend:** Python 3.11+, FastAPI, LangGraph, LangChain, Pydantic, HTTPX

**AI and data:** Google Gemini, Open Food Facts

## Run locally

### 1. Backend

Create a virtual environment and install the Python dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r app/requirements.txt
```

Create `app/.env`:

```env
GOOGLE_API_KEY=your_google_api_key
```

Start the API from the project root:

```bash
fastapi dev app/main.py
```

The API runs at `http://localhost:8000`.

### 2. Frontend

In another terminal:

```bash
cd client
npm install
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

Open `http://localhost:3000`.

If `NEXT_PUBLIC_API_URL` is not set, the frontend uses local mock data. This is useful for UI development without the backend.

## API

### `POST /analyze`

Request:

```json
{
  "query": "Nutella"
}
```

The response uses `text/event-stream`. Events expose graph progress, state updates, generated text, completion, or a safe error message.

## Current scope

The current version accepts a product name or barcode and analyzes text ingredient data available in Open Food Facts. Image and label scanning are not included yet.
